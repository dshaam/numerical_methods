# Задание №5. Вычисление собственных чисел матрицы

Реализация трёх методов вычисления собственных пар вещественной матрицы:
прямой степенной метод, обратный степенной метод со сдвигами и
QR-алгоритм со сдвигами и понижением размерности (deflation).

## Постановка задачи

По размерности `n` генерируется случайная диагональная матрица `Λ` (её
диагональ — заведомо известные собственные числа) и случайная невырожденная
матрица `C`. Рабочая матрица

```
A = C⁻¹ Λ C
```

подобна `Λ`, поэтому имеет те же собственные числа, но уже "перемешанные" —
на ней и тестируются все три метода.

Допуски, заданные условием:

| Обозначение | Смысл | Значение |
|---|---|---|
| `δ` (delta) | порог отсечения малых координат вектора при усреднении в степенном методе | `1e-8` |
| `rtol` | относительная точность собственного числа в степенном/обратном степенном методе | `1e-6` |
| `ε` (epsilon) | порог малости поддиагонального элемента для исчерпывания в QR-алгоритме | `1e-8` |

## Структура файлов

```
main.py               — точка входа, генерация A и запуск методов
power_method.py        — прямой степенной метод
inverse_iteration.py   — обратный степенной метод со сдвигом
QR_algorithm.py         — приведение к форме Хессенберга + QR-алгоритм со сдвигами
```

---

## 1. `power_method.py` — прямой степенной метод

Находит собственное число, наибольшее по модулю, и отвечающий ему собственный
вектор.

**Алгоритм:**
1. Стартовый вектор `y₀ = (1, ..., 1)`, нормируется: `z₀ = y₀ / ‖y₀‖`.
2. На каждой итерации: `yₖ₊₁ = A zₖ`, затем `zₖ₊₁ = yₖ₊₁ / ‖yₖ₊₁‖`.
3. Оценка собственного числа — покоординатное отношение `yₖ₊₁[i] / zₖ[i]`,
   усреднённое по координатам, где `|zₖ[i]| > δ` (чтобы не делить на
   величины, близкие к нулю).
4. Критерий остановки — относительное изменение оценки `λ` между
   итерациями меньше `rtol`.

**Возвращает:** `(λ, z)` — собственное число и нормированный собственный
вектор.

Ограничение метода: находит только одну (доминирующую по модулю) пару, и
работает надёжно, если такое собственное число единственно и по модулю
строго больше остальных.

---

## 2. `inverse_iteration.py` — обратный степенной метод со сдвигом

Находит собственную пару, ближайшую к заданному сдвигу `mu`. Позволяет,
перебирая разные `mu`, найти **все** собственные числа матрицы (в `main.py`
в качестве сдвигов берутся приближения `diag_elements - 0.2`, то есть
известные диагональные элементы `Λ`, слегка сдвинутые, чтобы матрица
`A - mu·E` не была вырожденной).

**Алгоритм:**
1. Те же `y₀`, `z₀`, что и в степенном методе.
2. На каждой итерации решается линейная система `(A - mu·E) yₖ₊₁ = zₖ`
   (через `np.linalg.solve`, а не явное обращение матрицы) — это и есть шаг
   "обратной итерации", эквивалентный степенному методу для матрицы
   `(A - mu·E)⁻¹`.
3. `zₖ₊₁ = yₖ₊₁ / ‖yₖ₊₁‖`.
4. Оценка собственного числа `(A - mu·E)`: усреднённое отношение
   `zₖ[i] / yₖ₊₁[i]` по координатам с `|yₖ₊₁[i]| > δ`.
5. Критерий остановки — как в степенном методе, по `rtol`.
6. **Итоговое собственное число матрицы `A`** — это `λ + mu` (обратный сдвиг
   после того, как найдено собственное число сдвинутой обратной матрицы).

**Возвращает:** `(λ + mu, z)`.

`main.py` вызывает этот метод для каждого `mu` из `diag_elements - 0.2` и
печатает найденную пару — так собираются все `n` собственных чисел матрицы.

---

## 3. `QR_algorithm.py` — QR-алгоритм со сдвигами и понижением размерности

Находит **сразу все** собственные числа матрицы без явных начальных
приближений.

### 3.1 Приведение к форме Хессенберга — `hessenberg_form(A)`

Использует отражения Хаусхолдера для обнуления поддиагональных элементов
ниже первой поддиагонали, столбец за столбцом (`k = 0, ..., n-3`):

- Для столбца `k` берётся поддиагональная часть `x = A[k+1:, k]`.
- Если она уже нулевая (кроме первого элемента) — столбец пропускается.
- Вычисляется `s = sgn(a) · ‖x‖`, где `a = A[k+1, k]` — знак берётся таким
  же, как у `a`, для устойчивости (избегание катастрофического сокращения).
- Строится вектор Хаусхолдера `v` (нормированный, `mu = 1/√(2s(s-a))`),
  отражение `Hₖ = I - 2vvᵀ`.
- Матрица обновляется как подобное преобразование: `A ← Hₖ A Hₖ` (так как
  `Hₖ` симметрична и ортогональна, `Hₖ⁻¹ = Hₖ`), что сохраняет собственные
  числа.

Результат — верхняя форма Хессенберга (нули строго ниже первой
поддиагонали).

### 3.2 QR-разложение вращениями Гивенса — `qr_givens(H)`

Так как `H` уже хессенбергова, для зануления каждого поддиагонального
элемента достаточно одного вращения Гивенса на пару соседних строк — всего
`n-1` вращение, как и требует условие задания.

- `givens_rotation(x, y)` возвращает `c, s` такие, что вращение обнуляет
  `y`, оставляя `x` в виде `√(x²+y²)`.
- Для каждого `k = 0, ..., n-2` строится вращение `G`, зануляющее элемент
  `R[k+1, k]`, применяется к строкам `k, k+1` матрицы `R` (только к
  ненулевой, "рабочей" части, начиная со столбца `k`) и накапливается в `Q`
  (правое умножение на `Gᵀ`).

Возвращает `Q, R` такие, что `H = Q R`.

### 3.3 Основной цикл — `qr_algorithm(A, max_iter=10000)`

1. `A` приводится к хессенберговой форме `H`.
2. Активный размер `m` изначально равен `n`; собственные числа "исчерпанной"
   части накапливаются в массиве `eigenvalues`.
3. Пока `m > 1`:
   - Если поддиагональный элемент `H[m-1, m-2]` по модулю меньше `ε` —
     блок разделился: `H[m-1, m-1]` — готовое собственное число,
     размерность активного блока понижается (`m -= 1`), поддиагональный
     элемент обнуляется явно.
   - Иначе выполняется QR-шаг со сдвигом (сдвиг Рэлея —
     `mu = H[m-1, m-1]`, последний диагональный элемент активного блока):
     `Hm - mu·I = Q R`, затем `Hm ← R Q + mu·I` — это ускоряет сходимость
     поддиагонального элемента к нулю по сравнению с QR-алгоритмом без
     сдвига.
   - Считается число итераций `total_iter`; если превышен `max_iter` —
     возвращается `None` (алгоритм не сошёлся).
4. Когда `m` доходит до 1, оставшийся `H[0,0]` — последнее собственное
   число.

**Возвращает:** `(eigenvalues, H)` — массив собственных чисел и итоговая
(почти) треугольная форма Хессенберга после исчерпывания.

⚠️ Метод даёт **только собственные числа**, без собственных векторов (в
отличие от степенного и обратного степенного методов).

## 4. `main.py` — сборка и демонстрация

```python
n = 6
diag_elements = np.random.randint(-10, 10, size=n)   # диагональ Λ (истинные λ)
lambdaa = np.diag(diag_elements)
C = np.random.randint(-10, 10, size=(n, n))
C_inverse = np.linalg.inv(C)
A = C_inverse @ lambdaa @ C                            # рабочая матрица
```

Далее для каждого приближения `mu = λᵢ - 0.2` (то есть рядом с каждым
истинным собственным числом) вызывается `inverse_iteration(A, mu)`, и
печатаются найденные `λ` и собственный вектор `v`.

Вызовы `power_method(A)` и `qr_algorithm(A)` в текущей версии файла
закомментированы — их можно раскомментировать, чтобы дополнительно
проверить прямой степенной метод и QR-алгоритм на той же матрице `A`.

### Как запустить

```bash
python main.py
```

Пример вывода (числа будут случайными при каждом запуске):

```
[[ 3  0  0  0  0  0]
 [ 0 -7  0  0  0  0]
 ...]
lambda = 3.0000000123
v = [ ... ]

lambda = -7.0000000089
v = [ ... ]
...
```

Первая матрица в выводе — `Λ` (истинные собственные числа для сверки),
дальше — результаты обратного степенного метода по каждому сдвигу.

## 5. Замечания / возможные улучшения

- В `main.py` выбор сдвигов `diag_elements - 0.2` работает только потому,
  что истинные собственные числа заранее известны (они и есть диагональ
  `Λ`). На практике (когда `Λ` неизвестна) начальные приближения для
  обратного степенного метода обычно берут из грубой оценки — например, из
  результатов степенного метода или из диагонали `A` — либо запускают
  предварительно QR-алгоритм и уточняют его результат обратными
  итерациями.
- Если два элемента `diag_elements` случайно совпадут (или оба сдвига
  окажутся равноудалены от двух истинных чисел), `inverse_iteration` может
  сойтись к "не той" паре — стоит проверять уникальность найденных `λ`.
- В `power_method` и `inverse_iteration` возможно затухание/незавершение
  цикла, если знак `zₖ` "переворачивается" от итерации к итерации
  (собственное число отрицательно и метод не всегда гасит знакочередование
  за счёт усреднения) — на это стоит обратить внимание при сравнении с
  результатами QR-алгоритма.
- В `qr_algorithm` используется простейший сдвиг Рэлея (последний
  диагональный элемент активного блока); для ускорения сходимости в
  сложных случаях (комплексно-сопряжённые пары, близкие собственные числа)
  обычно применяют сдвиг Уилкинсона — в задании это не требуется, но может
  быть полезным улучшением.
